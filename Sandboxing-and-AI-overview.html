A safe place to run unsafe software.

A sandbox restricts what a program can reach, while letting us observe what it does.

What this has made possible

2018 / Email protection

Intercepting malicious attachments

The sandbox limits damage. The observations help defenders respond.

02 / Two different limits
02 / 05

The test can be fooled. The boundary can break.

Hiding malicious behaviour and escaping an isolated computer are different failures.

A

Evading observation

Some malware recognises the test environment and conceals its activity.

Activity concealedInside a test environment
The test may miss the threat

FinFisher / Microsoft, 2018. The malware resisted analysis; this example does not show a broken isolation boundary.

B

Defeating isolation

A flaw in the isolation software can let code reach the host computer.

Virtual machine
Host computer
Research demonstration
Vulnerability patched

KVM / Google Project Zero, 2021. A demonstrated route across the boundary, not an observed malware outbreak.

Evasion undermines what a test reveals. Escape undermines what it contains.

Sources [3], [4]. FinFisher: evasion of analysis. KVM: controlled research demonstration of a patched vulnerability.

05 / The connection changes the problem
05 / 05

An agent can cause harm without escaping.

Controlling a connection does not settle whether its permitted uses are safe.

Reported incident / July 2026

The sandbox held.
A person stopped the attack.

  • UK AISI deliberately enabled internet access.
  • The agent did not escape its virtual-machine sandbox.
  • A maintainer rejected a malicious code contribution.

AISI found no evidence of resulting real-world harm.

Tighter limits reduce risk, but may also remove capabilities that realistic tests need.
